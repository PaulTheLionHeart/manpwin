TieraZon and Flarium Filters

Overview

ManpWIN includes a collection of colouring filters derived from the TieraZon family of fractal programs, together with additional filters adapted from Stephen C. Ferguson's Flarium program.

These filters are selected using the Outside Filter control in the Fractal Options dialog. This arrangement is retained for historical compatibility with the original TieraZon implementation.

Unlike most ordinary outside filters, however, many TieraZon filters are capable of colouring both points which escape from the fractal and points which remain inside it.

For this reason, when a TieraZon filter is selected it takes precedence over ordinary inside-filter colouring.

TieraZon Filters

TieraZon filters use information collected while the orbit of each point is being calculated.

Different filters may use properties such as:

  • the real and imaginary components of the orbit;
  • the magnitude of the orbit;
  • the angle of the orbit;
  • iteration history;
  • minimum or maximum orbit values;
  • relationships between successive orbit positions;
  • other mathematical properties accumulated during iteration.

The resulting values are then used to determine the final colour of the pixel.

Because different filters examine different properties of the orbit, the same fractal can produce very different images simply by changing the selected TieraZon filter.

Flarium Filters

ManpWIN also includes a number of filters adapted from Flarium, the fractal program developed by Stephen C. Ferguson.

These filters extend the existing TieraZon filter collection and provide additional orbit-based colouring methods while retaining the mathematical behaviour of the original algorithms as closely as practical.

A number of older TieraZon and Flarium filters have also been repaired or updated so that they work correctly with the current ManpWIN rendering system.

The filters are available from the same Outside Filter selection used for the existing TieraZon filters.

Inside and Outside Colouring

Most ManpWIN outside filters are applied only to points which escape from the fractal.

TieraZon filters are different. Although they are selected from the Outside Filter control, some TieraZon filters calculate colours for both escaping points and points which remain inside the fractal.

When a TieraZon filter is active, its result therefore takes precedence over an ordinary inside filter.

This behaviour is intentional and preserves the way these filters are designed to operate.

Clouds

Clouds is a special orbit-density rendering method based on an idea from Flarium.

Clouds is not a separate fractal type. It is implemented as a TieraZon-style filter and uses the orbit generated while calculating the selected fractal.

Unlike normal fractal colouring, Clouds does not colour each starting pixel according to the final result of its own orbit.

Instead, Clouds paints the places visited by all the calculated orbits.

Orbit Density

Whenever an orbit point falls within the current image, the density count for the corresponding screen pixel is increased.

As more and more fractal points are calculated, frequently visited areas accumulate larger density values while less frequently visited areas retain smaller values.

The final image is therefore based on the density of orbit visits rather than on conventional escape-time colouring.

This can reveal structures and flow patterns which may not be visible using ordinary colouring methods.

Multithreaded Calculation

ManpWIN performs fractal calculations using multiple worker threads.

For Clouds rendering, each worker maintains its own local density map while calculating its assigned pixels.

When the fractal calculation is complete, these individual density maps are merged into a single image-wide density map.

The final Clouds image is then generated from the accumulated density values.

For large images, the density merge may take noticeably longer than the final colour-rendering stage. Progress is displayed in the ManpWIN status bar while the density maps are being merged.

Clouds Colour

The Clouds colour control in the Fractal Options dialog determines how the accumulated density values are converted into the final image.

Four rendering modes are available:

  • Linear Greyscale - density values are mapped directly to shades of grey.
  • Log Greyscale - logarithmic scaling is applied to the density values before they are mapped to shades of grey.
  • Linear Palette - density values are mapped directly through the current ManpWIN palette.
  • Log Palette - logarithmic scaling is applied to the density values before they are mapped through the current palette.

The default setting is Linear Palette.

Linear rendering tends to emphasise the highest-density parts of the image, while logarithmic rendering can reveal weaker density structures which might otherwise be difficult to see.

Ordinary and Perturbation Rendering

Clouds can be used with both ordinary fractal calculation and perturbation rendering.

When perturbation is being used, the orbit points generated during the perturbation calculation are accumulated into the same type of density map used by ordinary rendering.

The final image is therefore produced using the same Clouds density-rendering process in both calculation modes.

BLA and Clouds

BLA (Bilinear Approximation) is an acceleration technique used with perturbation calculations. It approximates groups of orbit iterations so that very deep zooms, particularly those requiring high iteration counts, can be calculated much more quickly.

BLA acceleration is automatically disabled when Clouds is active.

Clouds requires every orbit position because every visited point may contribute to the density image.

Because BLA can skip groups of individual orbit iterations, using it with Clouds would mean that some orbit visits were never recorded and the resulting density map would be incomplete.

For this reason ManpWIN automatically bypasses BLA while rendering Clouds.

Performance and Memory

Clouds may require more processing time and memory than conventional escape-time colouring.

In addition to calculating the fractal, ManpWIN must maintain density data for the image and merge the local density maps produced by the worker threads.

The difference is most noticeable with large images or calculations involving large numbers of iterations.

PAR Files and Animations

Clouds rendering settings are preserved in PAR files and animations.

When a Clouds PAR entry is loaded, ManpWIN restores the Clouds rendering mode along with the other fractal settings.

Clouds can therefore be used in normal ManpWIN animations, including zoom animations.

Each animation frame is rendered from the orbit density calculated for that frame.

Because the distribution and concentration of orbit visits can change as the view changes, the apparent brightness and structure of Clouds may also vary from frame to frame during an animation.

Using TieraZon and Clouds Filters

TieraZon and Flarium filters are selected from the Outside Filter control in the Fractal Options dialog.

The Fractal Options dialog can be opened using the X key.

For Clouds, select the appropriate Clouds filter and then choose the required rendering method from the Clouds colour control before pressing OK.

The Clouds colour control affects only Clouds rendering and has no effect on any other filter.

As with other ManpWIN colouring methods, the appearance of the result can depend strongly on the selected fractal, viewing area, iteration limit, palette, and other rendering parameters.

Notes

Not every TieraZon or Flarium filter is equally suitable for every fractal. Some filters depend on particular orbit characteristics and may produce very different results when used with different fractal types.

Clouds is fundamentally different from conventional pixel colouring because the final colour of a screen location depends on visits made by many different orbits rather than only on the orbit which started at that pixel.
